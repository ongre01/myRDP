# RDP-017 Windows 1차 Release 통합 테스트

## 구현 결과

Windows 1차 release 후보를 반복 가능한 방식으로 검증하는
`scripts/test-windows-release.ps1`을 추가했다. 이 도구는 Debug/Release application과
기존 Qt Test project를 별도 build directory에서 다시 build하고, 자동 테스트와 application
startup smoke test를 수행한 뒤 `build/rdp017-validation/RDP-017-report.md`에 결과를 기록한다.

Windows 기본 RDP Client/Server를 사용하는 두 조합은 화면과 실제 입출력 장치가 필요한
수동 시험이다. 도구는 이 결과를 자동 테스트 성공으로 추정하지 않는다. 두 결과가 명시적으로
`Passed`일 때만 종합 결과를 `Passed`로 판정하며, 기본값인 `NotRun`이면 `Incomplete`로 남긴다.

## 자동 Release gate

기본 실행은 다음과 같다.

```powershell
pwsh -File scripts/test-windows-release.ps1 -RequireInterop
```

검증 항목은 다음과 같다.

- 최상위 `QtRdp.pro`의 Debug/Release build
- `RdpServerTest` Debug/Release build 및 실행
- Client channel, clipboard codec, clipboard UI bridge test의 Debug/Release build 및 실행
- offscreen `RDPClient` process startup
- 격리된 임시 설정과 동적 loopback port를 이용한 `RDPServer --background` listener startup
- `mstsc.exe` 및 Windows `TermService` 사용 가능 여부
- local Windows RDP default listener(TCP 3389) 사용 가능 여부

Server smoke test는 source `RDPServer.ini`나 기존 build output을 수정하지 않는다. 검증 전용
directory에 executable과 runtime DLL을 복사하고 사용 가능한 동적 port로 별도 INI를 생성한다.
Smoke test가 시작한 process는 성공/실패와 관계없이 종료한다.
각 실행은 고유한 smoke directory를 사용하므로 이전 수동 검증 process가 남아 있어도 새
검증 산출물을 덮어쓰지 않는다.

Qt qmake가 `PATH`에 없으면 `C:\Qt\*\msvc2022_64\bin\qmake.exe`에서 최신 Qt를 찾는다.
자동 탐색이 불가능한 환경에서는 다음처럼 명시한다.

```powershell
pwsh -File scripts/test-windows-release.ps1 `
  -QMakePath C:\Qt\6.11.0\msvc2022_64\bin\qmake.exe
```

일반 PowerShell에서 실행해 `INCLUDE`와 `LIB`가 비어 있으면 Visual Studio 2022의
`vcvars64.bat`를 찾아 MSVC x64 build 환경을 자동으로 초기화한다. 이미 Developer PowerShell인
경우에는 현재 환경을 그대로 사용한다.

`-RequireInterop`을 지정하면 수동 결과가 하나라도 `NotRun`인 경우 exit code 2를 반환한다.
Build, 자동 test, smoke test 또는 명시적으로 기록한 수동 test가 실패하면 exit code 1이다.

## 수동 상호 운용성 Matrix

각 조합은 아래의 모든 항목을 확인한 경우에만 `Passed`로 기록한다.

| 조합 | 필수 확인 항목 |
| --- | --- |
| QtRdp Client → Windows RDP Server | Client 실행, TLS certificate 판단, 인증, Desktop 표시와 갱신, keyboard, mouse 이동/button/wheel, Client→Server 및 Server→Client Unicode text clipboard, 정상 disconnect |
| Windows RDP Client → QtRdp Server | `--background` Server 실행과 listener, `mstsc` 연결, Desktop 표시와 갱신, keyboard, mouse 이동/button/wheel, Client→Server 및 Server→Client Unicode text clipboard, connect/disconnect 상태 및 background process 유지 |

### QtRdp Client → Windows RDP Server

1. 시험 대상 Windows host에서 Remote Desktop을 활성화하고 시험 계정을 준비한다.
2. Release `RDPClient.exe`를 실행해 host, port, username/domain/password를 입력한다.
3. 처음 보는 certificate 정보가 대상 host와 일치하는지 확인한 뒤 이번 연결에 한해 신뢰한다.
4. 원격 Desktop에서 text editor를 열어 keyboard 입력과 mouse 이동/button/wheel을 확인한다.
5. 한글, 영문, 줄바꿈을 포함한 text를 양방향으로 복사해 내용이 동일한지 확인한다.
6. Disconnect 후 Client가 연결 전 UI 상태로 돌아가는지 확인한다.

### Windows RDP Client → QtRdp Server

1. Release `RDPServer.ini`의 listen address/port가 시험 환경과 충돌하지 않는지 확인한다.
2. `RDPServer.exe --background`를 실행하고 tray 상태 또는 log에서 listener 시작을 확인한다.
3. `mstsc.exe /v:<server>:<port>`로 연결하고 self-signed certificate 경고의 대상 주소를 확인한다.
4. 전달된 Desktop을 갱신하고 keyboard 및 mouse 이동/button/wheel이 Server host에 적용되는지
   확인한다.
5. 한글, 영문, 줄바꿈을 포함한 text를 양방향으로 복사해 내용이 동일한지 확인한다.
6. `mstsc`를 종료하고 session count가 0으로 돌아가며 Server가 background에서 계속 실행되는지
   확인한다.

## 결과 기록

두 수동 조합을 완료한 뒤 동일 build에 대해 다음처럼 최종 report를 생성한다.

```powershell
pwsh -File scripts/test-windows-release.ps1 `
  -QtClientToWindowsServer Passed `
  -WindowsClientToQtServer Passed `
  -OperatorNote "시험 host와 실행 담당자 또는 결과 추적 번호" `
  -RequireInterop
```

수동 시험에서 문제가 발견되면 해당 값을 `Failed`로 기록하고 `-OperatorNote`에 재현 환경과
증상을 남긴다. Password, private key, clipboard 원문 같은 비밀 정보는 report에 기록하지 않는다.

자동화된 자체 Client↔Server protocol test는 실제 FreeRDP transport/TLS/cliprdr를 사용하여
연결, certificate 거부/승인, Desktop frame/dirty update, keyboard, mouse, 양방향 Unicode text
clipboard, disconnect/reconnect를 검증한다. 다만 Windows 기본 Client/Server 및 실제 device adapter
상호 운용성을 대체하지 않으므로 위 수동 Matrix는 release 완료 조건으로 유지한다.

## 2026-09-18 검증 기록

Qt 6.11.0 MSVC 2022 64-bit와 저장소의 FreeRDP build를 사용해 검증 도구 자체와 현재 source를
확인했다.

- Debug/Release `RDPClient`와 `RDPServer` build 성공
- Debug/Release `RdpServerTest`, Client channel test, clipboard codec test, clipboard UI bridge
  test 성공
- Debug/Release Client offscreen startup 및 background Server 동적 loopback listener smoke test 성공
- `mstsc.exe`와 실행 중인 `TermService`, TCP 3389 Windows listener 확인
- Release QtRdp Server의 격리 port에 `mstsc` 실제 연결 및 Desktop 표시/갱신 확인
- 원격 화면에서 Start menu와 Notepad taskbar를 click해 Server host UI가 변경되는 mouse 경로 확인

마지막 `mstsc` 확인은 같은 Windows desktop으로 loopback한 시험이었다. 원격 click이 시험 PC의
foreground window도 바꾸므로 keyboard, wheel, 양방향 clipboard를 독립적으로 판정할 수 없었다.
또한 Windows RDP Server 접속에 사용할 별도 시험 credential이 없어 반대 방향은 실행하지 않았다.
따라서 생성 report의 두 수동 조합은 `NotRun`, 종합 결과는 `Incomplete`로 유지했다. 별도 Windows
host/VM과 시험 credential을 사용해 수동 Matrix 전체를 통과하기 전에는 RDP-017 완료로 판정하지
않는다.
