# RDP-015 Server 설정 및 Logging 구현

## 구현 결과

`RDPServer.ini` 기반 Server 설정과 level별 파일 logging을 추가했다. GUI는 실행 파일과
같은 디렉터리의 설정 파일을 시작 시 읽고, `ListenAddress`와 `RdpPort`를 화면에 반영한다.
설정 파일이 없으면 코드의 안전한 기본값을 사용하며, 파일이 있지만 값이 잘못된 경우에는
Server 시작을 막고 오류를 표시한다.

qmake build는 `RDPServer.ini`를 Debug/Release 실행 파일 디렉터리에 함께 복사한다.

## 설정 파일

기본 설정은 다음과 같다.

```ini
[Server]
ListenAddress=0.0.0.0
RdpPort=3389
Authentication=Disabled
Certificate=
PrivateKey=
NtlmSamFile=
Capture=Desktop
MaximumClientCount=1
LogLevel=Info
LogFile=RDPServer.log
```

| 키 | 값 및 동작 |
| --- | --- |
| `ListenAddress` | listen할 IPv4/IPv6 주소. 빈 값은 모든 interface를 뜻한다. |
| `RdpPort` | `1`~`65535` 범위의 RDP port이다. |
| `Authentication` | `Disabled` 또는 `Nla`. `Nla`는 NLA로 인증된 연결만 허용한다. |
| `Certificate` | TLS X.509 certificate 파일. 상대 경로는 INI 파일 기준으로 해석한다. |
| `PrivateKey` | certificate와 쌍을 이루는 PEM private key 파일이다. |
| `NtlmSamFile` | 선택적인 FreeRDP NTLM SAM 파일이다. 상대 경로를 지원한다. |
| `Capture` | 현재 지원하는 값은 `Desktop`이다. |
| `MaximumClientCount` | 동시에 실행할 session 상한이며 `1`~`1024` 범위이다. |
| `LogLevel` | `Debug`, `Info`, `Warning`, `Error`, `Off` 중 하나이다. |
| `LogFile` | append할 log 파일. 상대 경로는 INI 파일 기준으로 해석한다. |

`Authentication`은 호환성을 위해 `false`/`0`을 `Disabled`, `true`/`1`을 `Nla`로도
읽는다. `Certificate`와 `PrivateKey`가 모두 비어 있으면 기존처럼 process 수명 동안 사용할
ephemeral self-signed certificate를 생성한다. 하나를 지정하면 다른 하나도 반드시 지정해야
하며 두 파일 모두 읽을 수 있어야 한다.

## 검증과 runtime 적용

`RdpServerSettings`가 INI parsing과 상대 경로 해석을 담당하고,
`RdpServerConfiguration::validate()`가 다음 오류를 Server 시작 전에 거부한다.

- IP address 형식 오류
- port 또는 최대 client 수 범위 오류
- 지원하지 않는 인증, capture, log level 값
- certificate/private key 중 한쪽만 설정한 경우
- 읽을 수 없는 certificate, private key, NTLM SAM 파일
- logging이 켜져 있는데 log 파일 경로가 비어 있는 경우

검증된 설정은 listener와 새 session에 snapshot으로 전달된다. 최대 session 수에 도달하면 새
socket을 즉시 닫고 Warning log를 남긴다. `Authentication=Nla`이면 FreeRDP NLA security를
활성화하고 익명 TLS/RDP logon callback을 거부한다. 외부 certificate/key가 있으면 각
session의 FreeRDP server settings에 이를 설치한다.

## Logging

`RdpServerLogger`는 여러 listener/session thread에서 동시에 사용할 수 있도록 mutex로
직렬화하며, UTF-8 text를 append한 뒤 각 event마다 flush한다. 형식은 다음과 같다.

```text
2026-09-18T02:30:15.123Z [INFO] [Client connect] Session 1 accepted from localhost.
```

낮은 심각도의 message는 설정된 `LogLevel`에서 걸러진다. 파일에 기록된 동일 event는
`RdpServer::logMessage` signal로 GUI event log에도 전달된다. 기록 대상은 다음과 같다.

- Server start / stop
- Client connect / disconnect와 최대 접속 수 거부
- Session worker, post-connect, activate, transport 종료 상태
- NLA 또는 익명 연결의 authentication result
- Desktop capture 초기화, 해상도 조회, frame 오류
- FreeRDP protocol 및 virtual channel 오류
- Listener/session wait와 socket 계층의 network 오류

비밀번호와 private key 내용은 log에 기록하지 않는다.

## 자동 검증

`RDPServer/tests/tst_rdpserver.cpp`에 다음 검증을 추가했다.

- 유효한 INI의 전체 설정 load와 상대 log 경로 해석
- 잘못된 address/port/authentication/capture/client 수/log level 거부
- Warning log level에서 Debug message filtering 및 Warning/Error 기록
- 최대 client 수 초과 연결 거부와 해당 Warning log 확인
- 기존 TLS 연결, desktop frame, input, clipboard, disconnect/reconnect 회귀 검증

Qt 6.11.0 MSVC 2022 64-bit 환경에서 다음 결과를 확인했다.

- Debug `RdpServerTest`: 15 passed, 0 failed
- Release `RdpServerTest`: 15 passed, 0 failed
- RDPServer Debug/Release build 성공
- Debug/Release 실행 파일의 offscreen startup smoke test 통과
- 두 build의 실행 파일 디렉터리에 `RDPServer.ini` 배치 확인

Compile warning은 FreeRDP/WinPR public header의 기존 deprecated 선언이다. 실제 domain 또는
NTLM SAM을 이용한 NLA credential interoperability와 운영 인증서 chain 검증은 자동 테스트에
포함하지 않았다.
