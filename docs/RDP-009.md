# RDP-009 RDP Server Test Frame 전송

## 구현 결과

`RdpServerSession`의 임시 TCP disconnect 감시 loop를 실제 FreeRDP server peer
처리 loop로 교체했다. 각 session worker가 RDP 협상과 client event를 처리하고,
client가 활성화되면 NSCodec으로 인코딩한 테스트 화면을 전송한다.

```text
RdpServerSession worker
  |
  +-- FreeRDP peer negotiation / activation
  |
  +-- RdpTestFrameGenerator
  |     +-- color bars
  |     +-- 64 px grid
  |     +-- six-digit frame counter
  |
  +-- NSCodec
  |
  +-- SurfaceBits update
        |
        v
     RDP Client framebuffer
```

초기 update는 client가 요청한 desktop 크기의 전체 화면이다. 이후에는 500ms마다
frame counter 영역만 다시 생성하고 전송한다. 따라서 반복 갱신을 검증하면서 매번
전체 desktop을 인코딩하거나 보내지 않는다. client가 다시 활성화되거나 협상된
desktop 크기가 바뀌면 다음 update를 전체 frame으로 전환한다.

## Test pattern

`RdpTestFrameGenerator`는 platform API나 Qt painting API에 의존하지 않고 BGRA32
pixel buffer를 직접 생성한다.

- 가로 방향 6색 color bar
- 64x64 단위 명암 패턴과 밝은 grid line
- 어두운 panel 위의 6자리 seven-segment frame counter

전체 frame과 counter-only frame은 같은 counter 위치를 사용한다. 부분 update의
좌표와 크기는 `SURFACE_BITS_COMMAND`의 destination rectangle에 전달되므로 client
framebuffer의 해당 영역만 바뀐다.

## RDP session 처리

session thread는 다음 순서로 동작한다.

1. `freerdp_peer_context_new()`로 server context를 만든다.
2. RDP security와 NSCodec, 32-bit color 설정을 적용한다.
3. 임시 2048-bit RSA 인증서와 key를 생성해 RDP security handshake에 사용한다.
4. `freerdp_peer::Initialize`를 호출한다.
5. peer event handle을 기다리고 `CheckFileDescriptor`로 protocol state를 진행한다.
6. activation callback 이후 전체 frame을 보내고 500ms 주기로 counter 영역을 보낸다.
7. client disconnect 또는 server stop 시 peer context와 codec 자원을 정리한다.

인증서와 private key는 process lifetime 동안 공유되는 임시 directory에 생성되며
process 종료 시 제거된다. 이는 test frame 단계의 개발용 RDP security material이다.
영구 인증서 설정과 TLS 호환성은 RDP-010 및 RDP-015 범위이다.

Windows에서 표준 RDP security에 필요한 RC4를 사용할 수 있도록 실행 파일 옆의
OpenSSL `legacy.dll` provider를 명시적으로 로드한다. 외부에서 `OPENSSL_MODULES`를
설정한 경우에는 해당 경로를 우선 사용한다.

## 자동 검증

`RDPServer/tests/tst_rdpserver.cpp`는 기존 listener/session 수명주기 검증에 다음을
추가한다.

- 640x480 BGRA32 전체 test frame의 크기와 유효성
- 연속 frame number가 서로 다른 counter pixel을 생성하는지 확인
- 실제 FreeRDP client와 loopback RDP security 협상
- server가 보낸 초기 전체 frame 수신
- 두 차례 이상의 반복 counter update 수신
- 세 frame 이후 client framebuffer 내용이 실제로 달라졌는지 hash 비교

Windows 기본 RDP Client의 TLS 연결 검증은 의존 관계상 RDP-010에서 수행한다.

## 검증 결과

Qt 6.11.0 MSVC 2022 64-bit와 저장소의 FreeRDP build를 사용해 다음을 확인했다.

- Debug 빌드 성공
- Release 빌드 성공
- `RdpServerTest` 6개 case 통과(init/cleanup 포함, 0 failed)
- loopback FreeRDP client가 초기 frame과 변경된 counter frame을 수신
- Release 실행 파일 offscreen startup smoke test 통과

빌드 warning은 FreeRDP/WinPR public header의 기존 deprecated 선언이며, 이번 구현
코드에서 추가된 warning이나 error는 없다. 기존 raw TCP session 종료 test는 의도적으로
RDP가 아닌 probe data를 보내므로 FreeRDP transport error log가 출력되지만 test 결과와
session 정리는 정상이다.
