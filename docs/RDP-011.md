# RDP-011 Windows Desktop Capture Platform Layer

## 구현 결과

RDP Server의 test pattern 전송 경로를 실제 Windows desktop capture 경로로 교체했다.
Application Layer인 `RdpServerSession`은 Windows API를 호출하지 않고
`DesktopCapture` 인터페이스를 통해 desktop 크기와 BGRA32 frame을 받는다.

```text
Windows Virtual Desktop
        |
        | GetSystemMetrics / BitBlt / CreateDIBSection
        v
WindowsDesktopCapture
        |
        | DesktopCaptureResult
        v
DesktopFrameBuffer -- 16x16 tile 비교 --> dirty rectangle
        |
        | BGRA32 frame
        v
RdpServerSession -- NSCodec / SurfaceBits --> RDP Client
```

플랫폼 factory인 `createDesktopCapture()`가 Windows build에서
`WindowsDesktopCapture`를 생성한다. 이후 macOS capture 구현을 추가할 때 세션과 RDP
전송 코드는 그대로 두고 factory의 platform 분기만 확장할 수 있다.

## Windows capture

`WindowsDesktopCapture`는 Windows virtual desktop의 origin과 크기를
`SM_XVIRTUALSCREEN`, `SM_YVIRTUALSCREEN`, `SM_CXVIRTUALSCREEN`,
`SM_CYVIRTUALSCREEN`으로 조회한다. 이 때문에 주 monitor의 왼쪽이나 위에 배치된 monitor도
포함할 수 있다.

화면 buffer는 top-down 32-bit DIB section으로 만들고 `BitBlt`의
`SRCCOPY | CAPTUREBLT`로 복사한다. Capture surface는 해상도 또는 virtual desktop origin이
바뀔 때만 다시 생성하고, 정상 종료 시 선택했던 GDI object와 DC를 역순으로 정리한다.

Capture 결과는 다음 세 상태를 구분한다.

- `FrameReady`: 전송할 전체 frame 또는 dirty frame이 있음
- `NoChanges`: 이전 capture와 동일하여 전송할 데이터가 없음
- `Error`: 해상도 조회, GDI resource 생성, `BitBlt`, buffer 할당 등에 실패함

Windows 오류에는 실패한 operation, Windows error code와 가능한 경우 system message가
포함된다.

## 변경 영역 처리

`DesktopFrameBuffer`는 마지막으로 성공한 전체 BGRA32 화면을 보관한다. 새 capture를
16x16 tile 단위로 비교하고 변경된 모든 tile을 포함하는 최소 bounding rectangle을 만든다.
RDP encoder에는 이 rectangle에 해당하는 pixel만 연속 buffer로 복사해 전달한다.

- 첫 capture와 강제 refresh는 전체 frame이다.
- 동일 frame은 `NoChanges`가 되어 RDP update를 보내지 않는다.
- 일부 변경은 16 pixel 경계의 dirty rectangle만 보낸다.
- 변경된 영역만 이전 frame buffer에 반영하여 매 capture마다 전체 이전 frame을 복사하지
  않는다.
- 해상도 또는 stride가 바뀌면 buffer를 재구성하고 전체 frame을 만든다.

현재는 여러 변경 영역을 하나의 bounding rectangle로 합친다. 따라서 서로 멀리 떨어진 두
영역이 동시에 변하면 그 사이도 포함되지만, 매번 전체 화면을 전송하는 방식보다 작은
update를 생성할 수 있고 향후 rectangle list로 확장할 수 있는 위치가 platform-independent
component로 분리되어 있다.

## 해상도 변경

Session 초기화 시 capture layer에서 실제 desktop 크기를 읽어 FreeRDP의
`DesktopWidth`와 `DesktopHeight`에 설정한다. Client가 다른 크기를 요청했으면
`PostConnect`에서 실제 크기로 맞춘 뒤 `DesktopResize`를 보낸다.

연결 중 display topology가 바뀌어 capture frame의 desktop 크기가 달라지면 다음 순서로
처리한다.

1. 현재 session의 frame 전송을 잠시 비활성화한다.
2. FreeRDP settings의 desktop 크기를 새 값으로 갱신한다.
3. `DesktopResize`로 client reactivation을 요청한다.
4. client가 다시 activate되면 전체 desktop frame을 강제로 capture하여 전송한다.

RDP SurfaceBits와 NSCodec의 frame 크기 한계 때문에 한 축이 `UINT16_MAX`를 넘는 desktop은
명시적인 session 오류로 처리한다.

## 오류 전달

Capture 생성 실패, desktop 크기 조회 실패, capture 실패, 잘못된 frame, resize 실패는
`RdpServerSession`의 error handler로 전달된다. `RdpServer`는 session id를 붙여
`lastError()`에 저장하고 기존 `errorOccurred` signal을 emit한다. GUI는 이 signal을 기존
error log와 status bar에 표시한다. 같은 session에서는 첫 오류만 보고하여 연쇄 실패가
log를 반복해서 채우지 않도록 했다.

## 자동 검증

`RDPServer/tests/tst_rdpserver.cpp`에 다음 검증을 추가하거나 갱신했다.

- 첫 frame이 전체 frame인지 확인
- 동일 frame이 `NoChanges`인지 확인
- 한 pixel 변경이 해당 16x16 dirty tile만 생성하는지 확인
- 해상도 변경이 전체 frame과 `desktopSizeChanged`를 생성하는지 확인
- 잘못된 capture buffer가 `Error`와 메시지를 반환하는지 확인
- 실제 `WindowsDesktopCapture`로 desktop 크기 조회 및 전체 frame capture
- TLS FreeRDP client가 실제 desktop frame을 받고 종료한 뒤 재연결 가능

Qt 6.11.0 MSVC 2022 64-bit와 저장소의 FreeRDP build를 사용해 다음을 확인했다.

- RDPServer Release 빌드 성공

확인은 이번 자동 검증에 포함하지 않았다.
