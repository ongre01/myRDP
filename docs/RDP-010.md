# RDP-010 Windows 기본 RDP Client 호환성

## 구현 결과

QtRdp Server가 표준 RDP security와 TLS security를 함께 지원하도록 server peer
설정을 확장했다. NLA/CredSSP는 아직 인증 계층이 없으므로 비활성 상태를 유지한다.
Windows Remote Desktop Client가 연결 협상에서 TLS를 요청하면 FreeRDP server가
`PROTOCOL_SSL`을 선택하고, process 시작 시 생성한 개발용 X.509 인증서와 RSA private
key로 TLS handshake를 수행한다.

```text
Windows Remote Desktop Client
        |
        +-- RDP Negotiation (TLS 선택)
        |
        +-- TLS handshake (개발용 self-signed 인증서)
        |
        +-- RDP activation
        |
        v
QtRdp Server -- NSCodec / SurfaceBits --> Test Frame
```

표준 RDP security도 fallback으로 유지하므로 TLS를 요청하지 않는 개발용 client와의
호환성을 잃지 않는다. 현재 인증서는 RDP-009에서 도입한 process-lifetime 임시
self-signed 인증서다. 영구 인증서 경로와 운영용 인증서 관리는 RDP-015에서 설정으로
분리한다.

## 연결 종료와 재연결

각 client는 독립적인 `RdpServerSession` worker에서 처리된다. client가 연결을 종료하면
peer event 처리 loop가 끝나고 TLS/RDP context, NSCodec context, frame stream을 정리한다.
listener는 계속 실행되므로 같은 주소와 port에 새 client session을 수락할 수 있다.

재연결 시 새 session은 다음 상태를 처음부터 다시 수행한다.

1. server peer context 생성
2. RDP/TLS capability 설정 및 인증서 연결
3. negotiation과 TLS handshake
4. RDP activation
5. 전체 test frame과 반복 counter update 전송
6. client 종료 후 session 자원 정리

## 자동 검증

`RDPServer/tests/tst_rdpserver.cpp`의 통합 test는 client에서 표준 RDP security와
NLA를 끄고 TLS만 허용한다. 이 설정으로 연결이 성공해야 server의 TLS negotiation과
handshake가 실제로 완료된 것이다. 연결 후에는 협상 결과가 TLS인지 확인하고 test
frame을 세 개 이상 받아 framebuffer가 변경되는지 검증한다.

첫 client를 정상 종료한 뒤 server session 수가 0이 되는 것을 기다리고, listener를
재시작하지 않은 채 두 번째 TLS client를 연결한다. 두 번째 client도 TLS 협상, 전체
frame, 반복 update, 종료까지 같은 검증을 통과해야 한다. 이 test로 다음 범위를
자동 검증한다.

- RDP connection 및 negotiation
- TLS-only handshake
- 초기 test frame 표시 데이터 수신
- 반복 frame update
- client disconnect와 session 정리
- 동일 listener에 재연결

## Windows Remote Desktop Client 확인 절차

1. QtRdp Server를 실행하고 listen address와 port를 설정한다.
2. `mstsc.exe`에서 `<server-address>:<port>`에 연결한다.
3. 개발용 self-signed 인증서 경고를 확인하고 연결을 계속한다.
4. color bar, 64px grid, frame counter가 있는 test frame이 표시되는지 확인한다.
5. counter가 약 500ms 간격으로 바뀌는지 확인한다.
6. client 창을 닫고 Server UI의 session 수가 0으로 돌아오는지 확인한다.
7. 같은 주소와 port로 다시 연결해 test frame이 다시 표시되는지 확인한다.

운영 환경에서는 self-signed 인증서 대신 접속 hostname과 일치하며 client가 신뢰하는
인증서를 사용해야 경고 없이 연결할 수 있다.

## 검증 결과

Qt 6.11.0 MSVC 2022 64-bit와 저장소의 FreeRDP 3.31.1 build를 사용해 다음을
확인했다.

- RDPServer Debug 빌드 성공
- RDPServer Release 빌드 성공
- Debug/Release `RdpServerTest` 각각 6개 case 통과(init/cleanup 포함, 0 failed)
- 각 test run에서 TLS-only client가 동일 listener에 두 번 연속 연결
- 두 session 모두 TLS 협상 후 초기 frame과 변경된 counter frame 수신
- 각 disconnect 후 active session 수가 0으로 복귀
- Release 실행 파일 offscreen startup smoke test 통과

컴파일 warning은 FreeRDP/WinPR public header의 기존 deprecated 선언이다. raw TCP
probe 및 정상 client disconnect 시 FreeRDP transport 종료 log가 출력되지만 test
결과와 session 정리는 정상이다.

Windows 기본 `mstsc.exe`를 사용한 시각적 연결 확인은 자동 OS 창 제어 runtime을
사용할 수 없어 이번 실행에서 완료하지 못했다. 위의 수동 확인 절차로 인증서 경고,
test frame 표시, 종료 및 재연결을 최종 확인해야 한다.
