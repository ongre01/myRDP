# RDP-007 Text Clipboard 연동 구현

## 구현 결과

`RDPClient`와 원격 RDP Server 사이에 `cliprdr` virtual channel을 사용한 양방향
Text Clipboard 동기화를 구현했다.

- Client에서 복사한 Unicode text를 원격 Server에 제공
- 원격 Server가 알린 Unicode text를 Client의 Qt clipboard에 적용
- 연결 직전의 Client clipboard 내용도 channel 준비 후 자동으로 알림
- 빈 clipboard를 길이 0인 문자열로 안전하게 동기화
- 연결 종료 시 channel callback, pending request, channel event 구독 상태 해제
- 원격 text를 Qt clipboard에 적용할 때 발생하는 `dataChanged` 재전송 방지

파일과 이미지는 이번 구현 범위에 포함하지 않는다. RDP text format은
`CF_UNICODETEXT`만 알리고 요청한다.

## 계층 구성

```text
QClipboard
  |
  | QString / dataChanged
  v
MainWindow
  |
  | sendClipboardText / clipboard text handler
  v
RdpClient
  |
  | CLIPRDR_FORMAT_LIST
  | CLIPRDR_FORMAT_DATA_REQUEST / RESPONSE
  v
FreeRDP cliprdr channel
```

`MainWindow`는 Qt clipboard 변경 감시와 원격 text 적용을 담당한다. `RdpClient`는
FreeRDP channel의 생성, protocol message, 연결 종료 정리를 담당한다.
`ClipboardTextCodec`은 두 계층과 분리되어 `QString`과 RDP의 UTF-16LE byte stream을
변환한다.

## Channel 초기화와 수명주기

연결 설정에서 `FreeRDP_RedirectClipboard`와 양방향 text clipboard feature mask를
활성화한다. `PreConnect` 단계에서는 FreeRDP channel connect/disconnect event를
구독한다. `cliprdr`의 `VirtualChannelEntryEx` 로딩은 `PreConnect`가 아니라 FreeRDP의
`LoadChannels` callback에서 수행한다. 전체 add-in 자동 로더는 기본 설정에 따라
clipboard와 무관한 `rdpdr`, audio, dynamic channel까지 로드할 수 있으므로 사용하지
않는다.

FreeRDP 3은 `PreConnect`가 반환된 뒤 기존 channel manager를 폐기하고 새 manager를
만든 다음 `LoadChannels`를 호출한다. 따라서 `PreConnect`에서 직접 로드하면 함수는
성공하더라도 실제 session에는 `cliprdr`가 남지 않는다. `LoadChannels`는 최초 연결뿐
아니라 redirection으로 channel manager가 다시 만들어질 때에도 호출되므로 항상 현재
manager에 `cliprdr`를 등록한다. 연결 완료 시 `cliprdr` interface가 session에 attach되지
않았다면 연결을 실패 처리하여 clipboard 비활성 상태가 조용히 지속되지 않게 한다.

`RdpClient`는 `freerdp_new`로 context를 직접 만드는 저수준 경로를 사용한다. 이 경로는
FreeRDP의 표준 client context 생성 함수와 달리 정적 channel add-in provider를 자동
등록하지 않는다. 따라서 context 생성 직후
`freerdp_channels_load_static_addin_entry`를 provider로 등록한 다음 `cliprdr` entry를
조회한다. 등록이 빠지면 channel 코드는 빌드되어 있어도 entry 조회가 실패한다.

`scripts/build-freerdp.ps1`은 `WITH_CHANNELS`, client/server channel과
`CHANNEL_CLIPRDR_CLIENT/SERVER`를 활성화한다. 설치 후 생성된 `freerdp/config.h`에
`CHANNEL_CLIPRDR_CLIENT`가 없으면 build script가 실패 처리한다. 기존에
`WITH_CHANNELS=OFF`로 생성한 FreeRDP install을 사용하는 경우 build script를 다시
실행한 뒤 `RDPClient`를 재빌드해야 한다.

`cliprdr` channel이 연결되면 다음 callback을 등록한다.

- `MonitorReady`
- `ServerCapabilities`
- `ServerFormatList`
- `ServerFormatListResponse`
- `ServerFormatDataRequest`
- `ServerFormatDataResponse`

Server의 monitor-ready message를 받으면 client capability와 현재 local clipboard의
`CF_UNICODETEXT` format list를 전송한다. Channel disconnect 시 `custom` context와
channel pointer, ready 상태, pending remote format을 초기화한다. RDP disconnect 후에는
channel event 구독도 해제하므로 재연결 시 이전 session callback이나 pointer가 남지
않는다.

## Client에서 Server 방향

Qt의 `QClipboard::dataChanged`를 감시하여 최신 text를 `RdpClient`에 저장한다. 아직
연결되지 않았거나 `cliprdr`가 준비되지 않은 경우에도 text를 cache하고, monitor-ready
이후 format list를 보낸다.

Server가 `CF_UNICODETEXT` data를 요청하면 다음 형식으로 응답한다.

- UTF-16 little-endian
- Windows 표준 CRLF 줄바꿈
- 마지막 UTF-16 null terminator 포함

빈 text도 실패 응답으로 처리하지 않고 UTF-16 null terminator 2 byte를 포함한 정상
응답으로 전송한다. 지원 범위 밖의 format 요청에는 `CB_RESPONSE_FAIL`을 반환한다.

## Server에서 Client 방향

Server format list에 `CF_UNICODETEXT`가 있으면 format-list 성공 응답 후 해당 data를
요청한다. 응답의 byte 길이가 홀수이거나 non-empty data pointer가 없으면 잘못된
UTF-16 data로 거부한다. 정상 data는 null terminator까지만 읽고 CRLF와 단독 CR을
Qt 표준 LF로 변환한 뒤 `MainWindow` handler에 전달한다.

Server가 빈 format list를 보내면 Qt clipboard를 빈 text로 갱신한다. 원격 text를
`QClipboard::setText`로 적용하는 동안 guard를 설정하여 동기식 `dataChanged` signal이
동일 내용을 Server로 다시 알리지 않게 한다.

## 검증

Qt 6.11.0 MSVC 2022 64-bit와 저장소의 FreeRDP build를 사용해 다음을 확인했다.

- Debug 빌드 성공
- Release 빌드 성공
- `ClipboardTextCodec` Qt Test 5개 case 통과(init/cleanup 포함 7 passed)
  - Unicode text와 surrogate pair round trip
  - LF에서 CRLF로 encode
  - CRLF와 단독 CR에서 LF로 decode
  - 빈 text encode/decode
  - 홀수 byte 길이 거부
  - UTF-16 null terminator 이후 data 제외
- `RdpClient` channel Qt Test 통과
  - 연결할 수 없는 loopback endpoint로 접속을 시도해 `LoadChannels`의 `cliprdr` 로딩을
    통과하고 실제 transport 연결 오류까지 진행하는지 확인
  - 같은 client instance에서 두 번 시도하고 `LoadChannels` 성공 횟수가 2인지 검사해
    실패 후 channel 정리와 재시도 경로 확인
- Release 실행 파일 offscreen startup smoke test

FreeRDP/WinPR public header의 기존 deprecated 선언 warning은 출력되지만 이번 변경에서
추가된 build warning이나 error는 없다.

접속 가능한 Windows RDP Server와 대화형 clipboard session이 제공되지 않아 실제
Windows application 사이의 복사/붙여넣기는 이번 자동 검증에 포함하지 않았다.
