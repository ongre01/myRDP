# RDP-016 Server 백그라운드 실행 및 자동 시작 구조 구현

## 구현 결과

RDPServer의 창 수명과 Server 수명을 분리했다. 애플리케이션이 시작되면
`RDPServer.ini`를 읽어 Server를 자동으로 시작하며, 설정 창을 닫아도 프로세스와 RDP
listener는 종료되지 않고 Windows 알림 영역에서 계속 동작한다.

## 실행 모드

- 일반 실행: 설정/상태 창을 표시하고 Server 시작을 시도한다.
- `RDPServer.exe --background` 또는 `-b`: 창을 표시하지 않고 Server 시작을 시도한다.
- Windows 자동 시작: 현재 사용자의 Run 레지스트리에 실행 파일의 절대 경로와
  `--background` 인자를 등록한다.

자동 시작 등록 위치는 다음과 같다.

```text
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
  QtRdpServer = "<RDPServer.exe 절대 경로>" --background
```

관리자 권한이나 시스템 전체 설정은 사용하지 않는다. 실행 파일을 다른 위치로 옮긴 경우
설정 창에서 자동 시작을 껐다가 다시 켜 새 경로를 등록해야 한다. Windows 이외의 플랫폼에서는
자동 시작 체크 상자를 비활성화하며, 향후 플랫폼별 구현을 추가할 수 있도록 등록 동작을
`AutoStartManager`로 분리했다.

## 알림 영역과 최소 GUI

알림 영역 메뉴에서 다음 동작을 사용할 수 있다.

- 현재 listener 상태, endpoint 및 활성 session 수 확인
- 설정 창 열기
- Server Start / Stop
- 애플리케이션 종료

설정 창의 닫기 버튼은 창만 숨긴다. 알림 영역의 `Exit`를 선택해야 Server를 Stop하고
프로세스를 종료한다. 시스템 트레이를 사용할 수 없는 환경에서는 일반 창 닫기 동작으로
종료할 수 있다.

설정 창에는 기존 endpoint, Start/Stop, session 수 및 event log와 함께 현재 Windows 사용자의
자동 시작 설정을 제어하는 체크 상자를 추가했다. 자동 시작 등록 실패는 상태 표시줄, event
log 및 경고 대화 상자에 표시한다.

## 오류 처리

백그라운드 자동 Start가 실패하면 프로세스는 상태 확인 및 재시작을 위해 계속 실행된다.
가능한 경우 알림 영역 메시지로 오류를 표시하고, 설정 창의 상태 표시줄과 event log에도
원인을 남긴다. 설정 창이나 알림 영역 메뉴에서 다시 Start할 수 있다.

## 검증

`RDPServer/tests/tst_rdpserver.cpp`에 실행 파일 경로를 따옴표로 감싸고 `--background`를
붙이는 자동 시작 명령 생성 검증을 추가했다. 실제 Run 레지스트리를 변경하는 테스트는 사용자
환경을 오염시키지 않기 위해 자동 테스트에서 수행하지 않는다.

Qt 6.11.0 MSVC 2022 64-bit와 저장소의 FreeRDP build를 사용해 다음을 확인했다.

- RDPServer Debug/Release build 성공
- Debug `RdpServerTest`: 16 passed, 0 failed
- Release `RdpServerTest`: 16 passed, 0 failed
- 일반 실행 시 `QtRdp Server` 설정 창 생성 확인
- 설정 창 닫기 요청 후 창 핸들은 사라지고 Server 프로세스는 계속 실행됨을 확인
- `--background` 실행 시 창을 만들지 않고 프로세스가 유지됨을 확인
- `--background` 실행에서 `0.0.0.0:33989` listener 생성 확인

실행 환경에서 Windows 원격 데스크톱 서비스가 기본 port 3389를 이미 사용 중이었으므로,
listener smoke test에는 build 출력의 runtime INI만 일시적으로 33989로 변경했다. 검증 후 해당
파일을 3389로 복구했으며 source의 `RDPServer.ini`는 변경하지 않았다. Compile warning은
FreeRDP/WinPR public header의 기존 deprecated 선언이다. 실제 Run 레지스트리 등록은 사용자
환경을 변경하므로 자동 검증에서 수행하지 않았다.
