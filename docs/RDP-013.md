# RDP-013 Server Clipboard 동기화

## 구현 결과

RDP Server에 FreeRDP `cliprdr` static virtual channel을 연결하고 Windows system
clipboard의 Unicode text를 양방향으로 동기화했다. Application/Protocol 계층은 Windows API를
직접 호출하지 않고 `ClipboardController` 인터페이스에만 의존한다.

```text
RDP Client
    |
    | cliprdr: FormatList / FormatDataRequest / FormatDataResponse
    v
RdpServerSession
    |
    v
RdpClipboardHandler -- UTF-16LE 변환 / 변경 추적 / echo 방지
    |
    v
ClipboardController
    |
    v
WindowsClipboardController -- Win32 Clipboard API --> Windows Clipboard
```

`createClipboardController()`는 Windows build에서 `WindowsClipboardController`를 생성한다.
향후 macOS 구현은 같은 인터페이스의 platform factory 분기만 추가하면 되며, FreeRDP channel
처리와 text codec은 재사용할 수 있다.

## FreeRDP cliprdr 수명주기

Server 시작 시 FreeRDP server WTS API function table을 등록한다. 각 `RdpServerSession`은
RDP channel join이 완료되는 `Activate` 시점에 client가 `cliprdr` channel에 참여했는지
확인한다. 참여한 session에만 virtual channel manager와 `CliprdrServerContext`를 만들고
다음 callback을 등록한다.

- Client capabilities
- Client format list / format list response
- Client format data request / format data response

Session worker의 wait set에는 peer event와 virtual channel manager event가 함께 포함된다.
Channel event가 신호되면 manager의 file descriptor를 처리해 초기 capabilities와 clipboard
PDU가 실제 transport로 전달되도록 한다. Session 종료 시에는 clipboard channel thread를 먼저
중지하고 context와 virtual channel manager를 정리한 후 peer context를 해제한다. Client가
clipboard redirection을 비활성화해 `cliprdr` channel에 참여하지 않은 경우에는
desktop/input session을 그대로 유지한다.

## Client에서 Server 방향

Client가 format list에서 `CF_UNICODETEXT`를 알리면 Server가 format list response를 보낸 뒤
해당 format data를 요청한다. 응답은 UTF-16LE로 검증 및 decode되고 Windows clipboard에
`CF_UNICODETEXT`로 기록된다.

Client clipboard가 비어 있거나 text format을 제공하지 않으면 Server의 text clipboard도
빈 text로 갱신한다. 홀수 byte UTF-16 data, null data pointer, 지원하지 않는 format과 channel
전송 오류는 명시적으로 처리한다.

## Server에서 Client 방향

Session worker는 Win32 `GetClipboardSequenceNumber()`를 이용해 local clipboard 변경을
감시한다. 변경이 있을 때만 `CF_UNICODETEXT` format list를 Client에 보내며, Client의 data
request 시점에 clipboard를 다시 읽어 최신 text를 반환한다.

Windows clipboard를 읽고 쓸 때는 다음 API를 Platform Layer 안에서만 사용한다.

- `OpenClipboard` / `CloseClipboard`
- `IsClipboardFormatAvailable`
- `GetClipboardData` / `SetClipboardData`
- `EmptyClipboard`
- `GlobalAlloc` / `GlobalLock` / `GlobalUnlock`

다른 process가 clipboard를 잠시 열고 있는 상황을 위해 `OpenClipboard`를 제한적으로
재시도한다. Local 변경 감시가 일시적으로 실패해도 RDP session 자체는 종료하지 않고 다음
poll에서 다시 시도한다.

## Text 변환과 loop 방지

RDP 전송 형식은 null terminator를 포함한 UTF-16LE이며 전송 시 line ending을 CRLF로,
application 내부에서는 LF로 정규화한다. 한글, supplementary pair를 포함한 UTF-16 code unit,
빈 문자열을 손실 없이 처리한다.

`RdpClipboardHandler`는 마지막으로 관찰한 clipboard sequence number를 보관한다. Remote
text를 Windows clipboard에 적용한 직후 새 sequence number를 기록하므로, 같은 변경을 다시
Client에 광고하는 echo loop를 만들지 않는다. 여러 Server session이 있으면 다른 session은
동일한 system clipboard 변경을 독립적으로 감지할 수 있다.

## 자동 검증

`RDPServer/tests/tst_rdpserver.cpp`에 가짜 `ClipboardController`를 사용한 검증을 추가했다.
Test는 실제 사용자 clipboard를 수정하지 않는다.

- Local text 변경 및 text format 제거 감지
- Server text의 UTF-16LE/CRLF encoding
- Client text의 decode와 Server clipboard 적용
- Remote text 적용 후 echo 억제
- 홀수 byte UTF-16 거부
- Platform controller factory 생성
- Clipboard read failure 전달
- 기존 TLS client desktop frame 수신 및 재연결 회귀 검증

## 검증 결과

Qt 6.11.0 MSVC 2022 64-bit와 저장소의 FreeRDP build를 사용해 다음을 확인했다.

- RDPServer Debug build 성공
- RDPServer Release build 성공
- Debug `RdpServerTest` 전체 통과
- Release `RdpServerTest` 전체 통과
- Debug/Release 실행 파일 offscreen startup smoke test 통과
- 기존 TLS client desktop frame 수신 및 재연결 test 통과

Compile warning은 FreeRDP/WinPR public header의 기존 deprecated 선언이다. Windows 기본
Remote Desktop Client 또는 외부 FreeRDP Client와 실제 system clipboard를 주고받는 수동
검증은 이번 자동 검증에 포함하지 않았다.
